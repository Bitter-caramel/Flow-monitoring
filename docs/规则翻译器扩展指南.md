# 规则翻译器扩展指南（给人和 agent 的改动地图）

> 版本：v1
> 日期：2026-10-05
> 状态：设计定稿，**待实施**（本文同时是"插件化搬家"的设计图纸）
> 配套：《规则翻译器.md》（架构与三层设计）、《定制化与检测规划.md》§4.3（兼容 Suricata 方向）
> 读者：后续的开发者 / AI agent —— **要给这个模块加关键字时，只看这一篇就够**

## 0. 一句话判据

> **加一个关键字 = 在对应分类目录里新增一个文件；不改任何现有文件。**

如果你为了加一个关键字改了别的地方，说明改错了位置。

---

## 1. 现状 vs 目标

| | 现状（搬家前） | 目标（搬家后） |
|---|---|---|
| 加一个关键字 | 改 `parse.go` 的 switch + 可能加 `ParsedRule` 字段 + 改 `normalize.go` 映射（**2~3 个文件**） | **新增 1 个 `kw/<类别>/<关键字>.go`** |
| 一个关键字的代码 | 散在 2~3 个文件里 | **全在 1 个文件里** |
| 能力清单 | 得从 `Unsupported` 反推 | `ls kw/meta kw/match kw/buffer kw/flow` 就是清单 |
| 管线层数 | lex → parse → normalize → compile | lex → **关键字插件（直接产出 IR）** → compile |
| 引擎热路径 | 不受影响 | **一样不受影响**（见 §5） |

> **为什么 parse 与 normalize 合并**：一个关键字的"读懂语法"和"翻译成 IR"本来就该在一起；分开只会导致同一个关键字要在两个文件里各写一遍。
> **真正要隔离的单位是「关键字」，不是「层」。**

## 2. 目标目录结构

```
internal/modules/rule/
├── ir.go                    [package rule]       IR 类型定义（稳定契约 = 核心）
├── compile.go               [package rule]       IR → CompiledRule（核心）
├── suricata/
│   └── lex.go               [package suricata]   词法切分（不认识任何关键字）
├── kw/                      # ★ 插件框架
│   ├── registry.go          [package kw]         注册表 + State + Handler 接口
│   ├── frame.go             [package kw]         规则头 → IR 骨架；选项循环；收尾
│   ├── meta/                [package meta]       msg / sid / rev / priority / classtype / reference / metadata
│   │   ├── msg.go
│   │   ├── sid.go
│   │   └── classtype.go
│   ├── match/               [package match]      content / pcre + 修饰项
│   │   ├── content.go
│   │   ├── pcre.go
│   │   └── modifiers.go
│   ├── buffer/              [package buffer]     7 个缓冲开关
│   │   └── buffers.go
│   └── flow/                [package flow]       flow
│       └── flow.go
└── pipeline/
    ├── translate.go         [package pipeline]   Translate 入口（+ 统计）
    └── imports.go           [package pipeline]   ★ 唯一的聚合文件：blank-import 上面所有子包
```

### 2.1 依赖方向（严格单向，绝不允许反向）

```
pipeline  →  kw/{meta,match,buffer,flow}  →  kw  →  {rule, suricata}
rule（IR + 编译）  →  什么都不依赖
suricata（词法）   →  只依赖标准库
检测引擎           →  rule（只吃 CompiledRule）
```

**核心（`rule`）完全不认识插件的存在**。这是"插件写崩了也拖不垮核心"的结构性保证。

> **为什么 `Translate` 搬到了 `pipeline`**：`kw/meta` 需要 import `rule`（用 IR 类型）；如果 `rule` 反过来 import `kw/meta`，就是循环依赖。所以入口必须站在更高的包上。
> **为什么必须有 `imports.go`**：Go 里子包不会被自动导入，`init()` 就不会执行。必须有地方把它们 blank-import（`import _ ".../kw/meta"`）。
> 好消息：**它只在"加类别"时才动，加关键字永远不用动。**

## 3. 插件框架（`kw/registry.go`）

```go
package kw

// State 翻译一条规则时的可变状态 = "正在构建的那条规则"。
type State struct {
	Raw         *suricata.RawRule // 词法结果（头字段：action/proto/ip/port…）
	Rule        *rule.Rule        // ★ 正在被写出来的 IR
	CurBuf      rule.Buffer       // 当前"粘性缓冲"（http_uri 这类开关改它）
	Unsupported map[string]int    // 不支持项计数
}

// Handler 一个关键字处理器。
// 约定：实现者只碰 st，不碰全局状态；重活（正则编译等）留到 compile 期。
type Handler interface {
	Name() string // 注册键 = 关键字名
	Handle(st *State, opt suricata.Option)
}

var registry = map[string]Handler{}

// Register 由各关键字文件的 init() 调用。重复注册在启动时 panic（不留到运行期）。
func Register(h Handler) {
	if _, dup := registry[h.Name()]; dup {
		panic("duplicate keyword: " + h.Name())
	}
	registry[h.Name()] = h
}

// Lookup 按关键字名取处理器。
func Lookup(name string) (Handler, bool) { h, ok := registry[name]; return h, ok }
```

**选项循环（在 `kw/frame.go`，永远不用再改）**：

```go
for _, opt := range raw.Options {
	if h, ok := kw.Lookup(opt.Key); ok {
		h.Handle(st, opt)          // ★ 查表分发，没有 switch
	} else {
		st.Unsupported[opt.Key]++  // 不认识的关键字记账（不报错）
	}
}
finalizeRule(st)                   // 收尾：填默认 Category/Severity/Action、ID、Source
```

## 4. 怎么写一个关键字插件（三个类别的完整例子）

### 4.1 缓冲类（最简单：只切换"后面 content 匹配哪块"）

```go
// kw/buffer/buffers.go
package buffer

import (
	"flow-monitoring/internal/modules/rule"
	"flow-monitoring/internal/modules/rule/kw"
	"flow-monitoring/internal/modules/rule/suricata"
)

// httpURI 声明 http_uri 缓冲：它不存数据，只切换后续 content 的匹配位置。
type httpURI struct{}

func (httpURI) Name() string { return "http_uri" }
func (httpURI) Handle(st *kw.State, _ suricata.Option) {
	st.CurBuf = rule.BufHTTPURI
}

func init() { kw.Register(httpURI{}) }
```

> 7 个缓冲开关（`payload` / `http_uri` / `http_header` / `http_method` / `http_client_body` / `dns_query` / `tls_sni`）
> 形态完全一样，可以写成一个「名字 → Buffer 枚举」的表，在 `init()` 里循环注册。

### 4.2 匹配类（content 本体 + 它的修饰项，**都在这一个文件里**）

```go
// kw/match/content.go
package match

type content struct{}

func (content) Name() string { return "content" }
func (content) Handle(st *kw.State, opt suricata.Option) {
	value, negate := stripNegate(opt.Value) // 处理 content:!"xxx"
	st.Rule.Match.Conditions = append(st.Rule.Match.Conditions, rule.Condition{
		Kind:   rule.CondContent,
		Buffer: st.CurBuf, // ← 用当前粘性缓冲
		Value:  value,
		Flags:  negateFlag(negate),
	})
}

func init() { kw.Register(content{}) }
```

```go
// kw/match/modifiers.go —— content 的修饰项都作用在"最后一个条件"上
func init() {
	kw.Register(nocaseMod{})   // Name() = "nocase"
	kw.Register(depthMod{})    // Name() = "depth"
	// offset / distance / within / fast_pattern 同理
}
```

### 4.3 元信息类（无值选项 / 有值选项 / 查表）

```go
// kw/meta/classtype.go
type classtype struct{}

func (classtype) Name() string { return "classtype" }
func (classtype) Handle(st *kw.State, opt suricata.Option) {
	st.Rule.Category, st.Rule.Severity = lookupClasstype(opt.Value) // 查内置表
}

func init() { kw.Register(classtype{}) }
```

> **加一类攻击 = 在 `lookupClasstype` 的表里加一行**（这是本来就已数据化的部分）。

## 5. 性能红线

**先记住一个事实**：

> **翻译器不在热路径上。** 它只在"导入规则"时跑一次。
> **热路径是检测引擎**——每个包都要跑的那条。

| 位置 | 要求 | 本设计怎么做 |
|---|---|---|
| 翻译路径（查注册表） | 不关键 | `map[string]Handler` 查表，**每"选项"一次**，无所谓 |
| **引擎热路径** | **零容忍** | ★ **编译期**就把"缓冲名 → 取内容函数"解析好，**函数指针存进 Matcher**；热路径**零查表、零动态派发** |
| 注册表并发 | 安全 | 只在**启动时**写、之后**只读** → 天然可并发读，不需要锁 |
| 核心模块稳定性 | **不能崩** | ★ **依赖方向单向**（插件 → 核心），核心不认识插件 |

编译期把提取函数固化进 Matcher 的形态（引擎侧约定）：

```go
type Matcher struct {
	// …
	Extract func(*datapacket.Packet) []byte // ★ 编译期解析好，热路径直接调
}
```

## 6. 加 / 改 / 删 一个关键字：操作清单

### 加一个关键字

1. 判断它属于哪一类：元信息（`meta`）/ 内容匹配（`match`）/ 缓冲开关（`buffer`）/ 流向（`flow`）。
2. 在对应目录新增一个文件（如 `kw/buffer/file_data.go`）。
3. 写一个实现 `Name()` + `Handle()` 的小类型，`func init() { kw.Register(xxx{}) }`。
4. 若它需要引擎侧"从包里取内容"，**那是引擎自己的注册表**，不在这里（见 §5）。
5. `go build ./... && go test ./internal/modules/rule/...` —— **不需要改任何现有文件**。

### 改一个关键字

只打开它自己那一个文件改。**改完必须跑测试**（§8）。

### 删一个关键字

删掉它那一个文件即可；跑测试确认没有残留引用。

### 加一个「新类别」

1. 新建子目录（如 `kw/behavior/`）。
2. 在 `pipeline/imports.go` 加一行 blank import。
3. 之后该类别里的关键字，加文件即生效。

## 7. 搬家蓝图（现状代码 → 目标文件）

> 这一节是**第③步"搬家"的操作图纸**：逻辑等价搬运，**不改行为**。

| 现在在哪 | 现状 | 搬到哪 |
|---|---|---|
| `parse.go` `case "msg"` | 存 Message | `kw/meta/msg.go` |
| `case "sid"/"rev"/"priority"` | `strconv.Atoi` | `kw/meta/sid.go` |
| `case "classtype"` | 存字符串 | `kw/meta/classtype.go`（**连查表与 severityWeight 一起搬**） |
| `case "reference"/"metadata"` | append | `kw/meta/reference.go` / `metadata.go` |
| `case "flow"` | 按 `,` 拆 | `kw/flow/flow.go`（复用现成的 `mapFlow`） |
| `case "content"` | append Content | `kw/match/content.go` |
| `case "pcre"` | append PCRE | `kw/match/pcre.go` |
| `case "nocase"/"fast_pattern"` | 改最后一个 content | `kw/match/modifiers.go` |
| `case "depth"/"offset"/"distance"/"within"` | Atoi 后改最后一个 content | `kw/match/modifiers.go` |
| `default` 里的 `bufferKeys` 分支 | 切 `curBuf` | `kw/buffer/buffers.go`（用表循环注册 7 个） |
| `default` 里的 Unsupported 分支 | 记账 | **框架**（`Lookup` 未命中时记，见 §3） |
| `normalize.go` `mapProto` / `parseNetSpec` / `parsePortSpec` | 头字段解析 | `kw/frame.go`（建 IR 骨架时调用） |
| `normalize.go` `mapFlow` | 流向 | `kw/flow/flow.go` |
| `normalize.go` `mapBuffer` | 缓冲名 → 枚举 | `kw/buffer/buffers.go` |
| `normalize.go` `classtypeTable` / `severityWeight` | 查表 | `kw/meta/classtype.go` |
| `normalize.go` `Normalize` | 组装一条 Rule | **框架**（`frame.go` 建骨架 + §3 的循环 + 收尾） |
| `translate.go` | 入口 + 统计 | `pipeline/translate.go`（**API 保持 `Translate(text) *TranslateResult` 语义不变**） |
| `ir.go` / `compile.go` / `suricata/lex.go` | —— | **不动** |
| `suricata/parse.go` | 语义解析 | **搬家后删除**（逻辑全部进入 `kw/*`） |
| `ParsedRule` / `Content` / `PCRE` 类型 | parse 层产物 | **搬家后删除**（不再需要中间层） |

**搬完的标志**：`suricata/` 下只剩 `lex.go`；`rule/` 下只剩 IR 与编译；所有关键字都在 `kw/*/`。

## 8. 维护约定（必须遵守）

1. **一关键字一文件**：一个关键字的所有支持代码（识别 + 写 IR + 它的修饰项）都在同一个文件里。
2. **不许反向依赖**：`rule` / `suricata` 绝不 import `kw`；`kw` 绝不 import `pipeline`。
3. **注册期 panic**：重复注册（两个文件抢同一个关键字名）在**启动时**就该炸，不要留到运行期。
4. **重活留给 compile 期**：正则编译、小写预转、端口索引等，都在 `compile.go` 做，不要在 `Handle()` 里做。
5. **改完必跑测试**：`go test ./internal/modules/rule/...`；golden 快照若 diff，**必须说明理由**再更新快照。
6. **不认识的关键字不报错**：记进 `Unsupported` 计数即可（导入报告会展示"哪些规则用了我们不支持的关键字"）。
