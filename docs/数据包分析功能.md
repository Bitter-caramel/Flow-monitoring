# 数据包分析功能（规划）

> **这份文档管什么**：在静态分析里，**辅助用户分析数据包**需要哪些功能、先后顺序、各自要什么后端能力。
> **不管什么**：开发总顺序（见 `docs/开发路线图.md`）、包详情本身（已完成，见下）。
> **原则**：效仿 Wireshark 的**基本盘**，不做全能版。**判断标准是"分析一段攻击流量时会不会用到"。**

---

## 0. 现在已有什么（2026-10-21）

| 能力 | 状态 |
|---|---|
| 按证据包切换（一处切换，告警/包列表跟随） | ✅ |
| 包列表分页（offset/limit） | ✅ |
| **包详情三段式**（协议分层树 / 十六进制 / 载荷） | ✅ |
| 告警 ↔ 包联动（告警行「查看包」） | ✅ |
| 详情缓存（TTL 5 分钟 / 容量 200） | ✅ |

**缺的是"从一堆包里找出要看的那几个"这件事。** 下面都是围绕它的。

## 1. 功能清单

### A. 查找（最高频）

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| A1 | **显示过滤器** | 类似 `ip.addr == 1.2.3.4`、`tcp.port == 80`、`http`、`dns` 的**简化语法**（不做完整表达式引擎）| **必须** |
| A2 | 关键词搜索 | 在 `Info` 列里做包含匹配 | **必须** |
| A3 | 按时间范围筛选 | 起止时间 | 应该 |
| A4 | 快速跳转 | 输入包号直接跳过去 | 应该 |

**后端需要**：`ListPackets` 增加过滤参数（`ip` / `port` / `proto` / `q` / `from` / `to`），走 SQL 条件。
**前端**：包列表上方一行过滤输入框（一个输入框 + 语法提示即可，不做多条件构建器）。

### B. 串联（把一个攻击流串起来）

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| B1 | **跟随流（按五元组）** | 给定一个包 ⇒ 只看同一 `(src,dst,sport,dport,proto)` 的所有包 | **必须** |
| B2 | 只看某个会话 | 从会话统计点进去 | 应该 |
| B3 | 同流上/下一个包 | 在详情里直接跳 | 应该 |

**后端需要**：`ListPackets` 支持 `flow=src,dst,sport,dport,proto` 过滤。
★ **不做**"重组后的连续字节流视图"（Follow Stream 的完整版）——那是另一个量级，等有真实需求再说。

### C. 统计（回答问题：这段流量里谁在大声说话）

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| C1 | **会话统计** | 五元组 → 包数 / 字节数 / 首末时间 | **必须** |
| C2 | 协议分布 | 各协议包数与占比 | 应该 |
| C3 | 时间分布 | 按秒/分钟聚合的包数（用于发现突发）| 应该 |

**后端需要**：新增 `GET /api/v1/captures/{id}/stats?group_by=flow|proto|time`（SQL GROUP BY）。
**前端**：表格即可，**不引图表库**（占比用文本+进度条）。

### D. 导出

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| D1 | 导出当前过滤结果为 pcapng | 只导出命中的包，便于交给别人或归档 | 应该 |
| D2 | 导出为 CSV | 元数据表 | 可选 |

**后端需要**：`pcapng` 已有 writer；新增 `POST /api/v1/captures/{id}/export`（带同样的过滤条件）。
★ 注意：导出的是**原始帧字节**，需要从源文件按包号取。

### E. 标记（人的记忆辅助）

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| E1 | 标记包 + 一句话备注 | 分析时标"这里是注入点" | 可选 |
| E2 | 只看已标记 / 跳到下一个标记 | | 可选 |

**后端需要**：新建表存 `(capture_id, packet_no, note)`，或先只做**浏览器本地存储**（刷新不丢、换机器丢）。
★ 建议**先做本地存储**，等需要协作时再入库。

### F. 导航

| # | 功能 | 说明 | 必要度 |
|---|---|---|---|
| F1 | 上一个 / 下一个包 | 详情里左右箭头，不改列表滚动位置 | **必须** |
| F2 | 相对时间 | 显示"距第一个包 +1.234s" | 应该 |
| F3 | 跳到首/末包 | | 可选 |

**纯前端**，成本极低，但**天天用**。

## 2. 明确不做（现在阶段）

- ❌ 完整 Wireshark 过滤表达式引擎（`&& || !` 组合、函数、正则）
- ❌ 着色规则（Colorize Rules）
- ❌ 实时抓包/实时分析（那是动态工作台的事）
- ❌ TLS 解密（独立方向 G）
- ❌ 可插拔协议解析器（Dissector 插件机制）
- ❌ 图表可视化库（统计用表格 + 文本条）

## 3. 建议顺序（按"用到的频率 ÷ 成本"排）

| 批次 | 内容 | 后端工作量 | 前端工作量 | 做完能干什么 |
|---|---|---|---|---|
| **第 1 批** | **A1 显示过滤器 + A2 关键词搜索 + F1 上下包** | 小（`ListPackets` 加条件）| 中 | **能在一堆包里定位到想看的**，这是最痛的点 |
| **第 2 批** | **C1 会话统计 + B1 跟随流** | 中（GROUP BY + flow 过滤）| 中 | 能看出"谁和谁说了多少"，并顺着一条流看下去 |
| **第 3 批** | D1 导出过滤结果 + A3 时间筛选 + F2 相对时间 | 中（pcapng writer 已备）| 小 | 能交付证据、能按时间定位 |
| **第 4 批** | C2/C3 协议与时间分布 + A4 快速跳转 | 小 | 小 | 辅助判断攻击形态 |
| **第 5 批** | E1/E2 标记与备注（先本地存储）| 小 | 中 | 分析过程中的记忆辅助 |

## 4. 依赖关系

```
A1 过滤器 ──┬──> A2 搜索（同一套条件拼接）
            ├──> D1 导出（复用过滤条件）
            └──> B1 跟随流（同样是一个过滤条件：flow=...）

C1 会话统计 ──> B2 只看某会话（点统计行跳过滤）
```

**关键**：A1 过滤器是所有后续功能的地基——**它把"过滤条件"变成一个可复用的东西**，
搜索、导出、跟随流都复用它。所以第 1 批必须先做 A1。
