## 1. 现在有什么（事实）

| 层 | 现状 | 说明 |
|---|---|---|
| **CSRF 防护** | 本轮（12-4a-补）落地 | 非 GET 的 `/api/*` 要求 `X-Flow-Request: 1` + `Origin` 同源校验 |
| **部署级 Token** | 本轮落地 | `auth.token` / `FLOW_API_TOKEN`；非回环监听且未配 token ⇒ **拒绝启动**；常量时间比较 |
| **审计** | 本轮落地 | 写操作落 `logs/audit.jsonl`（action/module/dry_run/result/remote/auth/origin/request_id） |
| **用户体系** | ★ **无** | 没有账号、没有密码、没有会话、没有角色 —— 本文要补的就是这个 |

★ 注意区分：**Token 是"部署级共享密钥"**（一条环境变量，给人/给 CI 用），**不是**用户体系 ✗。
两者要能共存：Token 用于"服务到服务/命令行"，用户体系用于"多人在同一实例上操作"。

## 2. 要做什么（候选方案，未拍板）

1. **账号**：`users` 表（id / username / password_hash / role / created_at / last_login）；
   ★ 密码用 **argon2id**（或 bcrypt）哈希，绝不存明文、绝不记日志；
2. **会话**：登录 ⇒ 签发会话（HttpOnly + SameSite=Lax cookie，或短期 JWT）；
   ★ 与既有 CSRF 头配合（cookie + 自定义头 = 双保险 ✓）；支持登出与过期；
3. **角色**：至少三档 —— `viewer`（只读）/ `operator`（可启停）/ `admin`（可改配置、管用户）；
   ★ core 模块的停用对**任何角色**都必须拒绝（现有硬约束 ✓ 不要被角色削弱 ✗）；
4. **审计打通**：`audit.jsonl` 增加 `user_id/username`（现在只有 `auth: token|none`）；
5. **引导**：首次启动如何创建第一个管理员？
   候选：① 启动打印一次性初始化 token ② 首次访问强制设置密码 ③ CLI `fmctl user add` ；
   ★ 倾向 ③（与"CLI 是同一服务层"的设计一致 ✓）；
6. **开发模式**：保留 `auth.dev_bypass: true`（**仅回环** + 显式开启）⇒ 不影响日常测试效率 ✓
   —— 这正是用户担心"影响测试效率"的解药 ✓。

## 3. 明确不做（本阶段）

- 不做 OAuth/SSO/LDAP（企业集成留到有真实需求时）；
- 不做细粒度权限（按模块/按面板的 ACL）—— 先三档角色；
- 不做密码找回/邮件（单机部署，用 CLI 重置即可）。

## 4. 验收判据（将来做时用）

1. 未登录访问 `/api/modules` ⇒ 401；登录后 viewer 能看、不能启停（403）；
2. operator 能启停但**停不了 core**（409）；
3. 审计里能区分**谁**做的（`username` 非空）；
4. `auth.dev_bypass=true` + 回环 ⇒ 无需登录（且启动日志**明确警告**该模式已开启）。
