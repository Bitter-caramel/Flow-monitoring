## 1. 定位：这是**给分析师用的安全运营控制台**，不是仪表盘

【已核实】项目定位是"围绕网络安全的流量检测：实时监测攻击流量、精准收集、复原攻击链、充当 IPS/IDS"
（用户原话）。⇒ 前端的第一服务对象是**专业分析人员**，参照系是
**【业界参照】** Wireshark / Kibana / Security Onion / Arkime / Brim(Zui) / Metasploit 这类工具，
**不是**营销型大卡片仪表盘。

**五条原则（按优先级）**
1. **信息密度优先**：一屏看到的有效信息越多越好；反对大留白、大圆角、装饰性动画；
2. **键盘优先**：常用操作有快捷键，`Ctrl+K` 命令面板是"什么都找得到"的兜底入口；
3. **数据区等宽字体**：IP / 端口 / 时间 / 十六进制字节一律等宽（对齐才可比较）；
4. **深色为主**：长时间盯屏、与终端一致；浅色作为可选项；
5. **一切都是面板**：与后端"万物皆插件"同构 —— 新功能 = 注册一个面板，不改外壳。

## 2. 现状诊断【已核实：读过 `frontend/src/**` 与 `package.json`】

| 项 | 现状 |
|---|---|
| 技术栈 | React 18 + TypeScript + Vite；**依赖只有 react/react-dom**（零 UI 库、零图表库） |
| 代码量 | ~800 行：`shell/App.tsx` **51 行**、`styles.css` **225 行**、两个面板各 ~120 行 |
| 外壳 | 两栏：左侧栏**平铺**列面板（图标+名+版本），右侧挂载选中面板 |
| 服务方式 | 后端 `internal/kernel/transport` 用 `http.FileServer` 托管 `frontend/dist` |
| ★ 已有但**没用上**的能力 | 注册表里已实现 `listByLayer()`（按 L0~L3 分组）⇒ 外壳却用 `list()` 平铺；`manifest.depends` 也只有校验、无联动 |

**缺口（这就是"差点意思"的来源）**：没有分层导航、没有顶栏/状态栏、没有路由（刷新即丢）、
没有设计令牌与主题、没有表格/树/虚拟滚动（几千行包列表会卡）、**面板之间无法联动**、没有可视化底座。

## 3. 技术选型（★ 已拍板）

| 维度 | 决定 | 理由 |
|---|---|---|
| 样式体系 | **Tailwind + 设计令牌 + 无头组件（headless）** | 面板是插件：插件必须**共用一套令牌**才能长得像一家人；大组件库会把它锁死 ✗，裸 CSS 又会让每个插件作者重复造轮子 ✗。★ 【已核实】Grafana 把令牌单独发成 npm 包（[@grafana/design-tokens](https://www.npmjs.com/package/@grafana/design-tokens/v/0.2.0?activeTab=dependents)）⇒ "令牌独立成层"是业界做法 ✓ |
| 可视化 | **自研 SVG / Canvas** | 零新依赖、完全可控、体积小；拓扑图/时间线/火花线都由我们自己画（见 §7） |
| 骨架 | **左导航按 L0~L3 分层 + 顶栏 + 底部状态栏**，**分两步**：先骨架+分层，再多面板工作区 | 一步到位做停靠式工作区风险大；先把"信息架构"立住 |
| 交互 | **命令面板（Ctrl+K）+ 快捷键 + 面板间联动**，分阶段做 | 专业工具的核心体验；也是"信息密度高"的必要配套 |
| 框架 | 沿用 React 18 + Vite（不动） | 已有插件注册表与两个可用面板，重写不划算 |

★ **借鉴方式**（用户要求）：**先看优秀案例再模仿** —— §10 列出"待功课清单"，
每开一个新组件（表格/拓扑/时间线）之前先做一次针对性功课，把参考实现记进本节。

### ★ 功课 #4 结论：令牌 / 主题 / 密度（12-4b-2 已做，2026-10-16）

- **参考**：
  - Grafana 把设计令牌**独立成 npm 包**（[@grafana/design-tokens](https://www.npmjs.com/package/@grafana/design-tokens)）
    ⇒ 令牌层与组件层解耦，换主题/密度只是换一组变量值；【已核实】。
  - Tailwind v4 是 **CSS-first**：原始令牌与语义映射直接写在 CSS 的 `@theme` / `@theme inline` 里，
    不再需要 `tailwind.config.js`（见 <https://tailwindcss.com/docs/theme>）。
- **我们抄了什么**：①令牌分三层（`tokens` 原始值 → `theme` 语义值 → 组件只读语义令牌），密度单列层；
  ②主题/密度用 `documentElement.dataset` 切换（`[data-theme]` / `[data-density]`），运行时零重渲染；
  ③"语义令牌 → 工具类"用 `@theme inline` 桥接，面板作者写 `bg-panel` / `text-dim` 即自动跟随主题与密度。
- **我们改了什么**：①不把令牌发成 npm 包（本项目单仓、外壳与面板同构建，发包是过度设计）；
  ②不引 Sass/构建期变量，直接用 CSS 自定义属性 + `color-mix()` 派生语义底色；
  ③密度只影响行高/内边距（`--row-h` / `--pad-*` / `--gap`），不动字号。
- **为什么不引运行时依赖**：令牌与主题是纯 CSS；引运行时主题库（CSS-in-JS / styled-components）会把
  "面板插件共用一套令牌"变成"共用一套 JS API"，等于把插件作者锁进某个库 ✗。
  CSS 变量 + dataset 零依赖、零重渲染、任何框架都能写面板 ✓。

## 4. 信息架构

```
┌─────────────────────────────────────────────────────────────────────┐
│ 顶栏：产品名 │ 全局搜索(Ctrl+K) │ 采集状态 │ 告警计数 │ 环境/连接指示 │
├──────────┬──────────────────────────────────────────────────────────┤
│ 左导航    │                    工作区（面板挂载点）                    │
│ (按层分组) │   ┌────────────────────┬─────────────────────────────┐   │
│ L0 内核  │   │  主面板             │  详情/辅助面板（可折叠）      │   │
│ L1 基础  │   │  （包列表 / 会话 /   │  （包详情 / 告警详情 /        │   │
│ L2 功能  │   │    规则 / 证据 …）   │    依赖拓扑 / 模块详情）      │   │
│ L3 扩展  │   └────────────────────┴─────────────────────────────┘   │
├──────────┴──────────────────────────────────────────────────────────┤
│ 状态栏：模块数/启用数 · 自检结果 · 留存与库状态 · 时间线滚动位置        │
└─────────────────────────────────────────────────────────────────────┘
```

**两种模式**（同一外壳，不同落点）：
- **概览**（`overview`）：态势一屏 —— 告警趋势、Top 会话、协议分布、模块健康；只读、少交互；
- **工作台**（`workbench`）：高密度分析 —— 包列表 / 会话 / 规则 / 证据 / **模块与依赖拓扑**；多面板、强交互。

★ **导航语义与 CLI 对齐**：CLI（`fmctl`）用 Unix 文件树语义（`tree`/`show`/`impact`），
Web 的左导航也用**同一套心智模型**（层级 > 模块 > 详情），
这样"**同一件事在 CLI 和 Web 上长得像**"，学习成本只付一次 ✓。

## 5. 设计令牌（Design Tokens）

**分层**：`tokens`（原始值）→ `theme`（语义化：`--fg-muted`/`--bg-panel`/`--accent-danger`）→ 组件只用语义变量。
★ 面板作者**只允许**使用语义令牌（不许写死颜色），这样换主题/调密度对插件自动生效 ✓。

| 类别 | 令牌（草案） |
|---|---|
| 颜色 | `bg-app` / `bg-panel` / `bg-elevated` / `border-subtle` / `border-strong` / `fg` / `fg-muted` / `fg-dim` / `accent` / **`danger`（攻击/告警）** / **`warn`** / **`ok`** / `link` |
| 语义色（安全域） | ★ 攻击/命中=暖红、可疑=琥珀、正常=青绿、信息=蓝灰；**色盲安全**：不能只靠颜色区分（配图标/形状） |
| 间距/密度 | 4px 基线；**三档密度**（`compact` 默认 / `normal` / `comfortable`）—— 表格与列表随密度切换行高 |
| 字体 | UI：系统栈；★ **等宽**：`JetBrains Mono`/`Cascadia Mono`/`ui-monospace` 回退栈，用于 IP/端口/字节/时间 |
| 圆角/阴影 | 小圆角（2~4px）、几乎不用阴影（层次靠边框与底色差） |
| 动效 | 只用于"状态变化可感知"（如新告警高亮淡入 200ms），禁止装饰性动画 |

## 7. 可视化策略（自研 SVG/Canvas）

1. **分层拓扑图（12-4 用）**：节点按 `layer`（L0~L3）**水平分层**，
   层内按"入度/名字"排序减少交叉；边按 `Via` 区分线型（`depends` 实线 / `provides:<能力>` 虚线）；
   ★ **不做花哨力导向动画**（那是装饰）—— 布局**确定性**优先，同一个图每次长得一样 ✓（便于比对截图与排错）；
2. **交互**：点节点 → 侧栏详情（版本/健康/启停/影响面）；hover 高亮"它的依赖"与"依赖它的"两侧；
   ★ 拖拽/自由布局（★★ 用户 2026-10-17 明确要求：拓扑图节点可自由拖动、不许写死）（用户已定：先静态拓扑）✓；
3. **性能边界**：模块级图（几十个节点）用 SVG 足够；★ 若将来画**主机/会话级**大图（上千节点）再换 Canvas 并做聚合 ✓；
4. 【业界参照】业界成熟做法是"分层/正交布局 + 确定性 + 弱动画"（如各类依赖图工具）；
   ★ 开写之前按 §10 做一次针对性功课并在此记录参考实现。

## 8. 面板契约的扩展（与后端对齐）

1. **面板 → 模块映射**：`PanelManifest` 增加 `moduleId?: string`；
   ★ shell 装配时**只显示对应后端模块已启用的面板**（当前前端是"编译进来就全注册"，不改就会出现
   "**模块停了、界面入口还在**"的假象 ✗）；
2. **模块启停界面**：直接消费 12-2/12-3 的服务层输出（`List`/`Graph`/`Impact`/`SelfCheck`），
   ★ **影响面绝不在前端自己算**（只渲染后端结果，否则与真实级联行为不一致 ✗）；
3. **面板间联动**：前端一条**上下文总线**（`selectedFlow` / `selectedAlert` / `selectedPacket` / `timeRange`），
   面板订阅自己关心的字段 ⇒ 例如"告警列表点一条 → 包列表过滤到该流 → 证据面板列出该连接"；
   ★ 约定与后端 `provides/injects` 同构（面板声明 `publishes`/`subscribes`），保持"万物皆插件"的一致性 ✓。
