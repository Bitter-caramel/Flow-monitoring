## 五、踩过的坑（别重复踩）

1. **别把压缩摘要当事实**：摘要说 `docs/模块启停与编译裁剪.md` 有 370 行，实际 251 行。
   → 凡要拿来做决策的数字/结论，重新 `read` 原文。
2. **MemoryBank 在项目外**（`D:\AAAGitProject\MemoryBank`），压缩后默认找不到。
3. **`git commit -m "...\"引号\"..."` 在 PS 5.1 会被切成多个参数**（报 `pathspec '默认' did not match`）。
   → 一律 `git commit -F <文件>`。
4. **`registry` 有"binary 为空则回退成 id"的老规则**：删 `binary` 后会让 `--list` 的 BINARY 列显示成模块 ID。
   → 内嵌模块必须 `&& !d.InProcess`。
5. **"在同一个进程"≠"同一个模块"**：`internal/modules/<x>` 里既有库（detect/rule/alert）也有进程模块实现（query/importer）。
6. **宿主进程（`cmd/server`）当前不跑检测**：`internal/hotpath` 只被 `cmd/parse-cli` 和测试调用。实时采集（`capture`）**一行没写**。
7. **`/enable` 走的是 `SetEnabledCascade` 而不是 `SetEnabled`**：在服务层加的哨兵错误，
   必须在 `transport.writeErr` 里补对应状态码，否则会掉进 default 的 **500**（语义拒绝被当成服务器错误）。
   → 加新哨兵错误时，**同时**检查 `writeErr` 与 `fmctl` 的文案映射。
