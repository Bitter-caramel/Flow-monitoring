## 五、踩过的坑（别重复踩）

1. **别把压缩摘要当事实**：摘要曾说某文档 370 行，实际 251 行。
2. **MemoryBank 在项目外**（`D:\AAAGitProject\MemoryBank`），压缩后默认找不到。
3. **`git commit -m` 含英文双引号会被 PS 5.1 切断** ⇒ 一律 `git commit -F <文件>`。
4. **`registry` 有「binary 为空则回退成 id」的老规则** ⇒ 内嵌模块必须 `&& !d.InProcess`。
5. **「在同一个进程」≠「同一个模块」**：`internal/modules/<x>` 里既有库也有进程模块实现。
6. **检测跑在 `capture` 插件进程里**，不在宿主：宿主只订阅 `detect.feature`（`internal/kernel/alerting`）。`internal/kernel` 禁止 import 业务包，由 `alerting/purity_test.go` 用 AST 守卫。
7. **`/enable` 走 `SetEnabledCascade`**：服务层加的哨兵错误，必须在 `transport.writeErr` 里补状态码，否则变 500。
8. **`Select-Object -First N` / `--limit` 会截断结果** ⇒ 「没搜到」不等于「没有」。已踩三次。
9. **测试构造错了会看起来像实现坏了**：14-1 里我在 public 段放 `sid:2000003` 想测"重复"，结果先被"越界"拦下——**重复必须发生在同一号段内**。
10. **`sqli.pcapng` 的 SQL 是 URL 编码的**（`%20UNION%20`）⇒ 规则写 `content:"UNION SELECT"`（含空格）永远匹配不到。
11. ★ **改 `internal/modules/**` 必须重编插件**（`go run ./cmd/fmbuild --modules=<x> --out bin/plugins`）：
    宿主与插件是两套构建，`go build ./cmd/server` 不会重编插件。16-2 因此出现过"代码改了、行为没变"的假象。
12. ★ **Windows 允许 `0.0.0.0:PORT` 与 `127.0.0.1:PORT` 同时监听，且更具体的地址优先**：
    起服务前必须确认"到底是谁在监听"（`netstat -ano | findstr :PORT`），否则会被残留进程劫持。
13. ★ **`wsl` / `docker` 的 stderr 会被 PowerShell 当成错误** ⇒ 明明 `ok` 却显示 `exit code: 1`。
    **判据：看输出里的 `ok` / `FAIL` 行和下文的真实退出码，不要只看 `$LASTEXITCODE`。** 已踩两次。
